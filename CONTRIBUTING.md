# Вклад в проект

## Рабочий процесс

1. Обновить локальную ветку `main`.
2. Создать отдельную ветку от `main`.
3. Внести одно логически связанное изменение.
4. Запустить проверки качества.
5. Открыть pull request и описать результат проверки.
6. Выполнить merge после review и успешного CI.

## Имена веток

Рекомендуемый формат:

```text
feature/world-bank-client
feature/raw-storage
fix/config-validation
docs/update-readme
```

## Сообщения коммитов

Рекомендуемые префиксы:

```text
feat: новая функциональность
fix: исправление ошибки
test: тесты
refactor: изменение структуры без изменения поведения
docs: документация
chore: инфраструктурные и служебные изменения
```

Пример:

```text
feat: add initial project configuration loader
```

## Локальные проверки

```bash
python -m ruff check .
python -m ruff format --check .
python -m mypy src
python -m pytest
```

Или:

```bash
make check
```

## Pull request

В описании PR следует указать:

- какую задачу решает изменение;
- какие файлы и компоненты изменены;
- как проверить результат;
- какие ограничения или следующие шаги остаются;
- проходят ли lint, type check и tests.

## Данные и секреты

Запрещено добавлять в репозиторий:

- `.env`;
- токены, пароли и ключи;
- реальные большие выгрузки World Bank;
- локальные Parquet, CSV и JSON из каталога `data/`;
- учетные данные Yandex Cloud.

Для тестов следует использовать небольшие fixtures, добавленные в `tests/fixtures/` в следующих pull request.
